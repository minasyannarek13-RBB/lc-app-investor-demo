# LC App Reveal Director Polish

Status: active presentation-only polish on `reveal-sales-v1`.
Production baseline: `main` / `lc.open-gamer.com` — DO NOT TOUCH until Founder approval.
Target: 9.3+/10 self-guided sales reveal.

## Core thesis
Live Casino has personalities. Traditional casino discovery hides them behind `Casino → Lobby → Game → Table → Seat`. LC changes the journey to `Discover → Person → Follow → Content / Schedule → Live → Licensed Operator → Return`.

Primary line: **Live Casino through people.**
Conceptual shift: **GAME / TABLE → PERSON**

LC owns discovery, creator identity, audience, content, following, schedules, live intent, social continuity, attribution/context, return loop and operator handoff. Licensed operators/providers retain game operation, streaming/game infrastructure, wallet, deposits/withdrawals, wagering, settlement, KYC/AML, responsible gaming and the regulated transaction.

## Director diagnosis
The current reveal is visually credible and functionally deep, but the Industry/Business story is still too generic. The biggest quality gain is not more product UI. It is making the two creator engines and the operator/provider economics unmistakable.

## P0 sales narrative

### 1. First 20 seconds
- 0–5s: `Live Casino through people.`
- 5–20s: show `Game / Table → Person` and the new journey.
- Do not lead with auth, compliance or internal labels.

### 2. Engine A — Dealer → Creator
Required story:
`Dealer → Persistent identity → Creator → Content → Followers → Schedule → Live → Operator → Return`

Required line:
**The dealer should not disappear when the shift ends.**

The audience must understand that LC potentially turns dealer talent from temporary table staff into a persistent creator/talent/distribution asset.

### 3. Engine B — Influencer → Live Casino
Required story:
`Influencer → Existing audience → Live Casino persona / dedicated event → Live intent → Licensed Operator → Return`

Required idea:
Live Casino can potentially acquire audiences by bringing creators into the format, not only acquire individual players through conventional marketing.

This remains a working product/business hypothesis to validate with pilots.

### 4. Operator — primary commercial audience
Do not sell a generic social network.

Show the mechanism:
`Creator → Audience → Live intent → Operator handoff → Regulated play → Creator-led reason to return`

Potential value to communicate without overclaiming:
- new discovery channel;
- creator-led acquisition;
- creator/session return loop;
- differentiated live formats;
- attributable intent/context;
- talent as potential distribution asset.

Never claim CAC, retention, GGR or ROI improvement without evidence.

### 5. Provider — second major commercial audience
Provider value must go beyond `distribution through people`.

Show four directions:
1. creator-led distribution;
2. influencer/dedicated live formats;
3. dealer/talent economics;
4. operating-model innovation.

Traditional:
`Central studio → Fixed tables → Scheduled dealer workforce → Operator distribution`

Potential extension:
`Creator / Dealer → Flexible talent → Dedicated creator session → Audience demand → Operator`

Required line:
**Potential to change Live Casino operating economics.**

Do not claim guaranteed OPEX reduction.

### 6. Studio / activation capability
Present only as proposed capability / operational concept:
- define operational requirements;
- design creator/influencer table or format;
- prepare studio setup;
- organize dealer/creator workflow;
- prepare launch framework;
- connect experience to operator/provider infrastructure.

Controlled mini-studio/distributed models are FUTURE OPERATING HYPOTHESIS only and must explicitly retain jurisdiction, licensing, certification, surveillance, equipment controls, game integrity, responsible gaming and operator/provider approval.

Never imply that regulated Live Casino can simply be streamed from an uncontrolled home setup.

### 7. Business & Monetization
Make this one of the strongest sections.

Start with value flow:
`Creator → Audience → Live intent → Operator → Gaming activity → Return`

Then show potential LC economics:
- operator SaaS/service fee;
- revenue-share where legally/commercially appropriate;
- creator monetization participation;
- tips participation;
- subscriptions/community;
- merchandising;
- studio/activation/operational services;
- provider/operator partnership economics.

All unconfirmed economics: `Working hypothesis / Illustrative / To be validated`.

The section must answer:
`WHY OPERATOR? · WHY PROVIDER? · WHY CREATOR? · WHY NOW? · HOW VALUE FLOWS? · HOW LC CAN MAKE MONEY? · WHAT MUST BE VALIDATED?`

Use a visual business-system map, not a finance spreadsheet or generic SaaS card wall.

## Required reveal sequence
1. **Thesis** — Live Casino through people.
2. **Shift** — Game/Table → Person.
3. **Player loop** — Discover → Person → Follow → Live → Operator → Return.
4. **Dealer engine** — Dealer → Creator.
5. **Influencer engine** — Influencer → Live Casino.
6. **Operator payoff** — creator-led intent/distribution/return while operator controls regulated play.
7. **Provider payoff** — creator formats + talent economics + potential operating-model innovation.
8. **Business & Monetization** — value flow first, economics second.
9. **Boundary** — LC is a layer, not the casino/wallet/KYC/wagering system.
10. **Payoff** — the table is temporary; the relationship can continue.

One dominant idea per screen.
